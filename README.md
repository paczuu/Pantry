# Pantry

A self-hosted **Progressive Web App** for household pantry and kitchen inventory. Scan barcodes, track expiry dates, share shopping lists, and keep notes and recipes in one place. Built for private installations where you control accounts, households, and access.

---

## Features

### Pantry and barcode scanner
- Scan EAN barcodes with the device camera (`html5-qrcode`): front/rear cameras, torch, beep.
- Manual barcode entry and products without a barcode.
- **Add mode:** scan → auto-fill product data → pick an expiry shortcut (+3 days, +1 week, +1 month, exact date) → save to the pantry.
- **Quick remove mode:** scan → match pantry items → subtract quantity (1, 2, 5, all) and mark as used or thrown away.
- Search-from-scanner on the pantry tab.
- Voice input for expiry dates (speech-to-date parsing).

### Product lookup
- Open Food Facts (food), plus optional Open Beauty Facts, Open Products Facts, and Open Pet Food Facts.
- Per-household barcode source order, country (for Open Food Facts), and enable/disable.
- Local SQLite catalog cache so scanned or custom products stay available offline from the server.

### Shopping, notes, and recipes
- Multiple shopping lists.
- Check off items in real time; transfer purchased items into a pantry location in one step.
- Add items that are expired or close to expiry onto a list.
- Color-tagged notes with pinning and checklists.
- Recipe collection with ingredients and ratings.

### Households, roles, and admin
- JWT login and registration.
- **First install:** the first registered user becomes household `ADMIN` and **system admin**, and a household is created automatically.
- Later users **cannot create a household**. They register only with a valid **invite code** (generated by admin with 5-minute lifetime).
- Household `ADMIN` can rename the household, generate invite codes, change member roles, and remove members.
- **System admin** (instance owner): list all users and households, create households, generate invite codes, grant/revoke system admin, and **delete a user including their account**.
- Audit log (household admin): who changed what and when (add, quantity, expiry, delete, transfer from shopping, and similar).

### PWA and realtime
- Installable on Android, iOS, Windows, and macOS (standalone PWA).
- Live updates over Socket.IO for shared household data.
- Customizable bottom navigation, accent theme, expiry warning window, categories, and household backup/restore.

## Requirements

- **Docker** (recommended for hosting), or
- **Node.js 18+** (20 or 22 recommended) and **npm** for local development

---

## Install with Docker

From the repository root:

```bash
docker compose up -d --build
```

The UI is served at **http://localhost:3200**. Nginx proxies `/api` and Socket.IO to the backend.

SQLite is stored on the host at `./data/pantry.db`.

Change `JWT_SECRET` in `docker-compose.yml` before exposing the instance. Keep `./data` backed up if you care about inventory and accounts.

Stop the stack:

```bash
docker compose down
```

## Local development (Node.js)

### 1. Backend

```bash
cd backend
cp .env.example .env
```

Set at least:

```env
PORT=3001
DATABASE_URL=file:./data/pantry.db
JWT_SECRET=change-me-to-a-long-random-string
NODE_ENV=development
```

Create the data directory if needed, then:

```bash
npm install
npm run prisma:generate
npm run prisma:push
npm run dev
```

API: **http://localhost:3001** (health: `GET /api/health`).

### 2. Frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

UI: **http://localhost:5173**. Vite proxies `/api` and `/socket.io` to the backend.

### 3. Optional root scripts

From the repository root (`package.json`):

```bash
npm run build          # frontend then backend
npm run build:frontend
npm run build:backend
npm start              # run compiled backend
```

## First login and invites

1. Open the app and **register** the first account (empty database). That user is household admin and system admin.
2. In **Settings**, generate an invite code (valid for 5 minutes) and share it.
3. Other people register with that code and join the household. They cannot create a household themselves.
4. System admins can create extra households and issue codes for those households from the system panel in Settings.

## Production notes

- Use a strong `JWT_SECRET`.
- Serve over HTTPS if you use the camera scanner or PWA install on phones (browser camera and install prompts typically need a secure origin).
- Put a reverse proxy in front of port 3200 if you expose the app on a domain.
- Do not share `.env` files or the SQLite database.
